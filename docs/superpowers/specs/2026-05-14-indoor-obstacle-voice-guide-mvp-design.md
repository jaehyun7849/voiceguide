# 실내 장애물 음성 안내 앱 MVP 설계

## 목표

사무실, 학교, 복도 같은 실내 공간에서 사용자가 이동할 때 전방 장애물을 음성과 진동으로 알려주는 Android MVP 앱을 만든다.

이 MVP는 길찾기 앱이 아니다. 지도, 목적지 안내, 경로 안내, 신호등 안내, 횡단보도 안내는 제공하지 않는다. 스마트폰 카메라에 보이는 장애물 후보를 감지하고, 그중 가장 중요한 위험을 짧게 설명하는 데 집중한다.

## 주요 사용 시나리오

사용자가 앱을 실행하고 스마트폰 후면 카메라를 앞쪽으로 향하게 든 채 실내 복도, 교실, 사무실 등을 이동한다. 앱은 실행 즉시 안내를 시작한다. 약 1.5~2초마다 카메라 화면을 분석하고, 가장 중요한 장애물을 골라 한국어로 안내한다.

안내 예시:

- "정면에 사람이 있습니다."
- "오른쪽에 의자가 있습니다."
- "왼쪽 가까이에 책상이 있습니다."
- "주의, 정면 가까이에 사람이 있습니다."
- "주의, 앞쪽에 계단이 있습니다."

## MVP 범위

첫 버전에 포함할 기능:

- 후면 카메라 미리보기와 프레임 수집
- 스마트폰 안에서 실행되는 온디바이스 객체 인식
- 1.5~2초마다 화면 분석
- 실내 장애물 인식 대상:
  - 사람
  - 의자
  - 책상 또는 테이블
  - 문
  - 계단
- 위치 안내:
  - 왼쪽
  - 정면
  - 오른쪽
- 대략적인 거리 또는 위험도 안내:
  - 보통
  - 가까움
  - 위험
- 한국어 음성 안내
- 진동 경고:
  - 가까운 장애물은 짧은 진동
  - 위험한 장애물은 긴 진동
- 간단한 조작:
  - 앱 실행 시 바로 안내 시작
  - 화면 전체 탭으로 일시정지 또는 재시작
  - 길게 누르기로 현재 상황 다시 설명

첫 버전에서 제외할 기능:

- 실외 도로 안내
- 차량과 자전거 인식
- 신호등과 횡단보도 인식
- 지도, 경로, 목적지 안내
- 미터 단위의 정확한 거리 측정
- 가까워짐/멀어짐의 안정적인 추적
- 서버 기반 이미지 분석
- 복잡한 접근성 설정 화면

## 권장 기술 방향

첫 MVP는 Kotlin 네이티브 Android 앱으로 만든다. 카메라는 CameraX를 사용하고, 음성 안내는 Android TextToSpeech, 진동은 Android Vibrator API, 객체 인식은 TensorFlow Lite 기반 온디바이스 모델을 사용한다.

카메라 미리보기는 부드럽게 유지하되, 객체 인식은 모든 프레임에서 실행하지 않는다. MVP에서는 약 1.5~2초마다 한 프레임만 분석하면 충분하므로 Kotlin 네이티브 Android 구조로도 성능 부담이 낮다.

첫 MVP는 온디바이스 객체 인식을 사용한다. 이렇게 하면 인터넷 연결 없이 사용할 수 있고, 카메라 프레임을 서버로 보내지 않아 개인정보 부담도 줄일 수 있다.

다만 나중에 모델을 바꾸거나 일부 분석을 보강할 수 있도록 구조는 열어둔다. 문, 계단, 벽처럼 막힌 공간을 감지하는 기능은 기본 객체 인식 모델만으로 약할 수 있다. 따라서 탐지기는 앱 전체에 직접 박아 넣지 않고, 교체 가능한 인터페이스 뒤에 둔다.

## 시스템 구성 요소

### 카메라

카메라 구성 요소는 후면 카메라를 열고 탐지기에 주기적으로 프레임을 전달한다. MVP에서는 모든 카메라 프레임을 분석하지 않는다. 배터리, 발열, 반복 음성 안내를 줄이기 위해 약 1.5~2초마다 한 프레임을 샘플링한다.

### 객체 탐지기

객체 탐지기는 이미지 프레임을 받아 감지된 물체 목록을 반환한다.

각 감지 결과에는 다음 정보가 포함된다.

- 객체 종류
- 신뢰도
- 화면 안 위치 박스

첫 구현은 가벼운 온디바이스 모델을 사용할 수 있다. 모델이 문이나 계단을 안정적으로 감지하지 못하면 해당 클래스는 기능 플래그로 감추거나, 이후 모델 업데이트에서 보강한다.

### 장면 해석기

장면 해석기는 객체 탐지 결과를 사용자가 이해할 수 있는 안내 정보로 바꾼다.

가로 위치는 화면을 3등분해서 판단한다.

- 왼쪽 1/3: "왼쪽"
- 가운데 1/3: "정면"
- 오른쪽 1/3: "오른쪽"

객체가 여러 영역에 걸쳐 있으면 위치 박스의 중심점을 기준으로 판단한다. 정면에 가까운 객체일수록 더 중요하게 본다.

거리는 실제 미터 단위로 계산하지 않고, 화면 안 객체 크기와 위치를 기준으로 대략 추정한다.

- 보통: 화면에 보이지만 작거나 중앙에서 벗어나 있음
- 가까움: 크기가 어느 정도 크거나 중앙에 가까움
- 위험: 중앙에 있고 크게 보임, 또는 충분한 신뢰도로 계단이 감지됨

이 값은 카메라 기반 위험 추정이며 실제 거리 측정이 아니다.

### 알림 관리자

알림 관리자는 무엇을 말할지, 언제 진동할지 결정한다.

보통 한 번의 분석 주기에는 장애물 하나만 안내한다. 중요한 장애물이 둘 이상일 때는 두 개까지 말할 수 있지만, MVP에서는 자세한 설명보다 짧은 안내를 우선한다.

우선순위:

1. 위험한 계단
2. 정면 가까이에 있는 사람
3. 정면 가까이에 있는 의자, 책상, 테이블
4. 정면의 문 또는 막힌 공간 후보
5. 왼쪽이나 오른쪽의 가까운 장애물
6. 멀리 있는 일반 물체

반복 안내는 줄인다.

- 같은 종류와 같은 위치의 안내는 약 4초 동안 다시 말하지 않는다.
- 위험도가 올라가면 쿨다운을 무시하고 즉시 다시 안내할 수 있다.
- 길게 누르기는 쿨다운과 상관없이 현재 상황을 다시 설명한다.

### 음성 안내 관리자

음성 안내는 한국어를 기본으로 한다. 일반 안내는 자연스러운 문장을 사용한다.

- "정면에 사람이 있습니다."
- "오른쪽에 의자가 있습니다."

위험 안내는 "주의"로 시작한다.

- "주의, 정면 가까이에 사람이 있습니다."
- "주의, 앞쪽에 계단이 있습니다."

MVP에서는 안내 문장을 짧게 유지하고, 계속 말이 이어지지 않도록 한다.

### 진동 관리자

진동은 위험을 보강하되 사용자를 피로하게 만들지 않아야 한다.

- 가까운 장애물: 짧은 진동
- 위험한 장애물: 긴 진동

진동 관리자는 알림 관리자가 실제로 안내할 가치가 있다고 판단한 경우에만 호출된다.

### 제스처 제어

전체 카메라 화면을 주요 조작 영역으로 사용한다.

- 탭: 안내 일시정지 또는 재시작
- 길게 누르기: 현재 상황 다시 설명

일시정지 상태에서는 카메라 미리보기는 유지할 수 있지만, 객체 탐지, 음성 안내, 진동은 멈춘다.

## 화면 구성

MVP 화면은 최대한 단순하게 만든다.

- 전체 화면 카메라 미리보기
- 화면 하단의 작은 상태 텍스트:
  - "안내 중"
  - "일시정지"
- 첫 버전에서는 복잡한 메뉴를 넣지 않는다.

앱은 화면을 보지 않아도 사용할 수 있어야 한다.

## 오류 처리

카메라 권한이 없으면 권한을 요청하고, 장애물 안내를 위해 카메라가 필요하다고 설명한다.

음성 합성 기능을 사용할 수 없으면 간단한 오류 상태를 보여주고 일시정지/재시작 조작은 유지한다. 이 MVP에서는 진동만으로는 충분하지 않으므로, 음성 안내 불가는 중요한 문제로 취급한다.

지원하는 물체가 감지되지 않으면 보통 아무 말도 하지 않는다. 길게 누른 상황 설명에서는 "감지된 주요 장애물이 없습니다."라고 말할 수 있다.

## 테스트 전략

MVP 검증 항목:

- 권한 허용 후 앱이 바로 카메라 안내 상태로 시작되는지 확인
- 탭으로 안내가 일시정지되고 다시 시작되는지 확인
- 길게 누르기로 최근 장면 요약이 다시 안내되는지 확인
- 가짜 탐지 결과를 넣었을 때 올바른 한국어 문장이 생성되는지 확인
- 왼쪽, 정면, 오른쪽 위치가 올바르게 분류되는지 확인
- 가까움과 위험 상태에서 기대한 진동이 발생하는지 확인
- 같은 안내가 쿨다운 동안 반복되지 않는지 확인
- 위험도가 높아졌을 때 쿨다운을 무시하고 다시 안내되는지 확인

수동 복도 테스트:

- 정면에 사람이 서 있는 상황
- 오른쪽에 의자가 있는 상황
- 왼쪽에 책상 또는 테이블이 있는 상황
- 앞쪽에 문이 있는 상황
- 계단 사진 또는 실제 계단이 있는 장소

## 구현 메모

첫 구현에서는 특정 모델을 앱 전체에 직접 연결하지 말고, 탐지기 인터페이스를 통해 사용한다. 이렇게 하면 첫 모델이 문이나 계단을 충분히 잘 감지하지 못하더라도 나중에 모델을 교체하거나 보강하기 쉽다.

첫 버전은 거리를 정확한 미터로 말하지 않고 "가까이에" 같은 표현을 사용한다. 카메라만 사용하는 탐지는 위험을 놓칠 수 있으므로, 앱은 강한 안전 보장을 암시하지 않아야 한다.
